# Testing

The tests use real files, real sensors and real location (fed to the emulator); there are no mocks. Everything here was run on emulators. A debug build (commit becfa3e) was run by the owner on a Pixel Watch 3 (API 37) on 2026-10-13.

## Read this before running the instrumented tests

The instrumented tests act on the app's real data on the device they run on. They delete every waypoint and crumb in the app's database, change its settings, and Gradle uninstalls the app when the run ends, which removes the app's data. A watch holding real waypoints loses them. Run them on emulators.

## Setup

- JDK 17 (`JAVA_HOME` at it; on this machine `export JAVA_HOME=$(/usr/libexec/java_home -v 17)`), and the Android SDK named in `local.properties`.
- `adb` is in `~/Library/Android/sdk/platform-tools/`; the scripts use it by that path.
- macOS has no `timeout` command; every script that waits has its own deadline.
- Emulators (AVDs, all arm64):

| AVD | API | System image |
|-|-|-|
| `Wear_OS_API33` | 33 (Wear OS 4) | `system-images;android-33;android-wear;arm64-v8a` |
| `Wear_OS_API34` | 34 (Wear OS 5) | `system-images;android-34;android-wear;arm64-v8a` |
| `Wear_OS_Large_Round` | 35 (Wear OS 5.1) | `system-images;android-35-ext15;android-wear;arm64-v8a` |
| `Wear_OS_Small_Round` | 35 | same as the large one, with a smaller screen |
| `Wear_OS_Newest` | 37 (Wear OS 7.0) | `system-images;android-37.0;android-wear-signed;arm64-v8a` |

- Keep exactly one emulator attached while working. The scripts and Gradle's connected tests assume a single device; `scripts/all-suites.sh` is the exception: it boots its four emulators side by side and names each by its serial (`EMULATOR_ONLY_SERIAL`, below), and stops all but the last one when it ends. `scripts/switch-emulator.sh <avd>` stops the attached one, boots the named one (`scripts/emulator.sh` does the booting and waiting, up to 5 minutes) and installs the debug app if it has been built.

## When to run what

- While working: the tests that cover the change, on the one emulator that is up. `scripts/relevant-tests.sh` lists them from the files changed (the working tree against HEAD, a git range, or one commit's own change: a single commit `<c>` is read as `<c>^!`) and prints the `scripts/quick-tests.sh` command that runs them; `scripts/quick-tests.sh <Class[#method]> ... [--unit <Class> ...]` runs them in one run of the test runner, in about the tests' own time plus 10 to 20 s (on 2026-10-16 on `Wear_OS_Large_Round`: `SettingsStoreTest DialInputsTest` 64 s from start to end, `LocationSourceTest TrueNorthTest --unit CheckTest` 24 s). Unit tests and lint are quick enough to run whole.
- At the hand-back of a fix round: unit tests, `./gradlew lintDebug`, and the device tests that cover what changed on API 37 (`Wear_OS_Newest`) and API 33 (`Wear_OS_API33`), the newest and the oldest image (`scripts/quick-tests.sh --avd <avd> ...` with both booted, or one after the other).
- At the end of a task, before review or a push: unit tests, lint, a debug build, and `scripts/all-suites.sh` once on the final code, which runs the whole suite on the four emulators at the same time. Not twice in one round, and not right after a narrow run failed: the failure is fixed with the narrow run first.
- What `scripts/relevant-tests.sh` cannot see: it matches names in the text of the sources. A test that reaches the changed code only through other code (most device tests go through `MainActivity` and the view model) is not listed unless its own source names a changed declaration, and a build file, the manifest or a script maps to nothing (it says so). That is what the full run at the end of a task is for.

## Unit tests

```
./gradlew testDebugUnitTest
scripts/test-counts.sh unit
```

They cover the pure functions in `nav/`, and the table of vibrations in `ui/Vibrations.kt` (`VibrationTableTest`), and need no device. `StaticInitOrderTest` loads `nav/Navigation.kt` and `nav/WatchColors.kt` afresh in a class loader of its own, one or the other first, and checks the ring's read offset and the first waypoint's color each way (it failed on the offset's old field form with Navigation.kt first). `WaypointPlacesTest` checks the places new waypoints are given (500 in a row, 5000 random sets of places already taken). `CalibrationTest` checks the calibration ring's regions with fifteen magnetometer vectors recorded from the API 37 emulator (each set through its sensor console and read back from `dumpsys sensorservice`), the heading error read from values[4], the `Calibrate` prompt's threshold and its margin (on above 30 degrees, off only below 25, `largeHeadingError`), that a field of any strength lights its region, the two-minute keep-on rule, and the ring's memory (`ringMemoryStep`, `ringMemorySettles`): a fall to low or unreliable clears the ring, another level is only kept, and a report below the level kept in the first 3 seconds after the sensor is registered, before one at that level or better, does not clear it (a start-up that reports unreliable, then low, then its level keeps the ring; a sensor that stays low past the 3 seconds clears it). `WatchColorsTest` and `ColorsSettingTest` check the gray schemes (`isGrayScheme`, a primary under 0.10 beside a tertiary or error color that is a color) with the scheme of the owner's watch (primary `#FFF9EB`, tertiary `#FFC0B7`, error `#FFBFB0`, `onSurface` `#EDE8DA`, `onSurfaceVariant` `#D3CEC1`, `outline` `#AAA699`): it is used (before watch-test fix round 1 the pointer was `#2F8BFF` and north `#FF3B30`), north has the tertiary's hue, 0.80 of saturation (the watch face's red `#FF3E32` has 0.80; before watch-test fix round 2 north was `#FF7865`, 0.60, and the error color the app's `#FF3B30`, 0.81, redder than north), is `#FF4D33` and has at least 6 to 1 on black, and 0.3 more saturation than the pointer, the pointer is a gray-red between the primary and north with 0.30 of saturation, the error color is `#FF7C65`, a gray-red between the pointer and north with 0.3 more saturation than the pointer and less than north (a scheme's error color `#FF5449` is kept, the app's `#FF3B30` is not), north has more saturation than each of the first fifty new waypoints, the ring's third anchor is the outline's gray, and the first eight new waypoints are grays or gray-reds, at least 12 apart in a channel from one another and 24 from north; no one of the first fifty new waypoints on the owner's scheme, nor of the first twenty on 1 000 or more random gray schemes, is within 24 in a channel of the error color or the pointer, the fifty are each their own place and color, and `Standard` and the schemes whose primary is a color give the same fifty places as without the colors (watch-test fix round 3), and the very fifty places, written in the test, that the code gave at commit 5a10810, before the rule; where every place of a gray palette is within 24 of the error color or the pointer (a crafted palette of one gray), new waypoints are given those same fifty places, each its own (the closing round); on random schemes the gray ones keep these bounds (and on 150 000, north has at least the error color's saturation, and the error color is told from the pointer or is north itself) and the others the rules as before. `TargetsTest`, `TrailTest` and `ReadoutTest` check the uncertain pointer (`directionUncertain`): a crumb 3 m away with a 30 m fix has no dial angle, is not arrived at and is not consumed, 100 m away it has its angle; arrival within 10 m is decided first; a waypoint 15 m away with a 30 m fix has no angle; another crumb that near has no tick; the readout writes `10 ft ±50 ft`, for a waypoint `49 ft ±98 ft`, and `(old)` instead with an old fix. `HeadingKindInUseTest` checks that a watch that cannot work out the magnetic heading runs the fused source whichever is asked for, and the check screen's `Magnetic unavailable` / `Blend unavailable`. `HeadingBlendTest` turns a fused heading that drifts 0.6 degrees a second through thirty full turns each way and checks that the blend stays within 5 degrees of the true heading. The second command prints each class's count and the total from the result XML, and exits 1 if a test failed or there are no results.

## Instrumented tests, one emulator

```
scripts/quick-tests.sh DialInputsTest SideButtonTest#withTheSettingOffAPressActsAtOnceAndTwoCloseTogetherStartNoTrail   # on the one emulator that is up
scripts/quick-tests.sh --avd Wear_OS_API33 CheckScreenTest --unit CheckTest # on one of several that are up
scripts/relevant-tests.sh                   # which classes cover the changes not yet committed
scripts/relevant-tests.sh HEAD~2..HEAD      # or those of a range of commits
scripts/relevant-tests.sh b218d82           # or of one commit (its parent to it)
```

`scripts/quick-tests.sh` builds the app and the test app once (`./gradlew assembleDebug assembleDebugAndroidTest`, a Gradle call of its own, so a failed build stops it before anything else), runs the named unit test classes in a second call (`testDebugUnitTest --tests`), then runs `scripts/device-tests.sh` on the emulator, which does what the suite needs and Gradle did: it lays the watch flat at a magnetic heading of 40 and checks the pose read back and that the screen is awake, sets up its cleanup (below) and its INT and TERM trap before it changes anything, uninstalls and installs the app and the test app (`~/Library/Android/sdk/platform-tools/adb -s emulator-5554 install -r -t`; no permission is granted at install, as with Gradle), sets the three animation scales to 0 and puts back afterwards those it set, starts `scripts/geo-feed.sh` and `scripts/field-requests.sh` for this emulator, lists the tests the run would run (`-e log true`), each install and that listing with 300 s before it is stopped and the run counts as not run (`scripts/deadline.sh`), runs `am instrument -r -w` with every name in one `-e class` list, stops the feed and the relay, and uninstalls both apps. It prints PASS, FAIL (with the first lines of the failure), SKIP or NOT RUN for each test and exits 1 on any of the last three. The runner drops a name that matches no test without a word when another name of the list matches (seen on API 37, 2026-10-16), so `scripts/quick-tests.sh` requires a result for each name given: `SettingsStoreTest WaypointDatabaseTest#nope` ran the 35 tests of the first, printed `NOT RUN WaypointDatabaseTest#nope` and exited 1; `NoSuchTest` alone is reported by the runner as `FAIL NoSuchTest#initializationError`. Results are in `app/build/quick-tests/<avd>/` (the runner's raw output with the time of each line, and `TEST-<avd>.xml` for `scripts/test-counts.sh device app/build/quick-tests/<avd>`). The command Gradle sends, read on the API 37 emulator while `connectedDebugAndroidTest` ran on 2026-10-16, is `am instrument -r -w -e class ... -e additionalTestOutputDir /sdcard/Android/media/com.infinite8looper.compass/additional_test_output com.infinite8looper.compass.test/androidx.test.runner.AndroidJUnitRunner`; during it the location permissions read `granted=false` and the three animation scales 0, and afterwards the scales were 1.0 again and both apps uninstalled. `scripts/device-tests.sh` sends the same.

Through Gradle, which runs the whole suite or one class per run:

```
scripts/switch-emulator.sh Wear_OS_Large_Round
scripts/geo-feed.sh -72.2896 43.7022 3000 > /dev/null 2>&1 &
ANDROID_SERIAL=emulator-5554 ./gradlew connectedDebugAndroidTest   # the emulator's serial, from `~/Library/Android/sdk/platform-tools/adb devices`
scripts/test-counts.sh device
pkill -f geo-feed.sh
```

- The position feed is needed by `LocationSourceTest`, by the `CompassViewModelTest` tests whose comments say so, by `InstantSaveTest`, `LocationOnScreenTest`, `TrueNorthTest` and `PressVibrationTest`, and by the tests that save a position through the real activity (`DialInputsTest`, one test of `AccessibilityTreeTest`, and `SideButtonTest` on a watch that describes a button). Android delivers location only to an app that is on screen, so those tests bring the real activity to the front themselves. `scripts/geo-feed.sh <lon> <lat> [seconds]` sends `~/Library/Android/sdk/platform-tools/adb -s emulator-5554 emu geo fix` once a second for that many seconds (120 if left out); the tests expect 43.7022, -72.2896.
- The build refuses to run the instrumented tests anywhere but on an emulator (`app/build.gradle.kts`): every `connected...AndroidTest`, `connectedCheck`, `deviceCheck` and `uninstall...` task fails before it does anything unless `ANDROID_SERIAL` is an emulator's serial (`emulator-NNNN`) and `~/Library/Android/sdk/platform-tools/adb devices` lists no device that is not an emulator. Without that, Gradle would run the tests on every device adb lists and wipe the app's data on each. Seen on 2026-10-13: with no `ANDROID_SERIAL`, with `ANDROID_SERIAL=localhost:5555`, and with `ANDROID_SERIAL=emulator-5554` while the emulator was also attached as `localhost:5555`, `connectedDebugAndroidTest` ended in `refusing: ...` and `BUILD FAILED` in under a second, and so did `uninstallDebug` with no `ANDROID_SERIAL`; with one emulator and its serial the tests ran. `installDebug` is not held back. `scripts/quick-tests.sh` and `scripts/all-suites.sh` do not run the tests through Gradle (`scripts/device-tests.sh` sends `am instrument` to the emulator named by its serial) and make their own checks.

That is `InstrumentationActivityInvoker$EmptyActivity`, a helper activity of the test library in the test package (`com.infinite8looper.compass.test`), which has a light theme; the app's own window was not in front in those frames (screen recording and `dumpsys window`, API 35, 2026-10-13). No white frame was recorded on a cold launch, a font size change, sleep and wake, Home and back, or a change of pose.

- `InstantSaveTest` saves from a position in hand that came from the geo console. `geo fix` and `geo nmea` take no accuracy. The API 33, 34 and 35 images give every position an accuracy of 5 m, so a more accurate position never comes from them; the API 37 image gives accuracies that vary (3.0 to 3.8 m seen on 2026-10-14), so there the view model's own updates refine saves as well. ## The backup agent, by the system's own backup

```
scripts/backup-off-check.sh        # API 33, 34 or 35: it needs adb root and sqlite3 on the device
```

The instrumented tests cannot run the system's backup of the app: a backup ends the app's process, which is the test's. This script runs the system's backup and restore from the host (`bmgr`) against the debug app as built, with the system's local transport, and reads the stored archive's entries with the device's `tar`. The transport is told what kind of pass it is through its own parameter (not encrypted, `is_encrypted=true`, `is_device_transfer=true`); under the last two the backup rules let the database and the settings file through, so that is where "the marker alone" is judged. Its cases are listed at the top of the script: the switch on in each kind of pass; the switch turned off through the question, in each kind; the app installed again from a transfer and from a backup (the switch off, no question, no database); the switch tapped on, a backup, an install (the waypoint back, the switch on); a switch owed off by a restore, with the settings writable and with the settings folder made unwritable; and the app's files folder made unwritable. It wipes the app's data, and puts the Backup Manager, the transport and the transport's parameter back as they were when it ends, and has a trap that does the same when it is stopped by INT, TERM or HUP (an interrupted run was not tried). Exit status 0 if every requirement held.

## What differs by image

- API 33 and Wear OS 7.0 (API 37): a change of pose sent through the emulator's console (`scripts/set-heading.sh`, `~/Library/Android/sdk/platform-tools/adb -s emulator-5554 emu sensor set acceleration ...`) puts the screen to sleep (seen on API 33 as `mWakefulness=Dozing` right after the command; on API 37 as activities that stay stopped). Why these two images do it was not looked into. An app on a sleeping screen is stopped and gets no position, so the tests that use the real activity then fail (23 and 22 of 134 in one run). Send `~/Library/Android/sdk/platform-tools/adb -s emulator-5554 shell input keyevent KEYCODE_WAKEUP` after changing the pose; `scripts/all-suites.sh` does. The API 34 and 35 images stay awake.

- API 33: no `~/Library/Android/sdk/platform-tools/adb -s emulator-5554 shell input rotaryencoder`; `scripts/crown.sh` writes the crown's events as root (`~/Library/Android/sdk/platform-tools/adb -s emulator-5554 root`, then `sendevent`) and says so; run `~/Library/Android/sdk/platform-tools/adb -s emulator-5554 unroot` afterwards. The image sometimes goes to ambient shortly after launch; `~/Library/Android/sdk/platform-tools/adb -s emulator-5554 shell input keyevent KEYCODE_WAKEUP` wakes it.
- Wear OS 7.0 (API 37, `Wear_OS_Newest`): a signed image, so there is no `~/Library/Android/sdk/platform-tools/adb -s emulator-5554 root` and no `sqlite3` on the device. `scripts/seed-targets.sh` changes a copy of the database file with this machine's `sqlite3` and puts it back; `scripts/raw-swipe.sh` sends the touch through the emulator's console instead of the device.
- `~/Library/Android/sdk/platform-tools/adb -s emulator-5554 shell input swipe` can drop the rest of a swipe when the app is slow on one sample; `scripts/raw-swipe.sh` writes raw touch events and is the one to use when the outcome of a swipe matters.

## Driving the app by hand

- Heading: `scripts/set-heading.sh <degrees>` lays the virtual watch flat and sets a magnetic heading; the reading takes about 20 seconds to settle, and with true north on, the dial shows the heading corrected by the declination. The default pose is upright, which is the hold-flat state.
- Saving from the compass: `scripts/double-tap.sh` (two `input tap` sent by one shell a tenth of a second apart, inside the double-tap time; it prints the gap there was). The side button's key, `~/Library/Android/sdk/platform-tools/adb -s emulator-5554 shell input keyevent KEYCODE_STEM_1`, does nothing on the emulators: the images describe no button, so the app installs no key handling. Crown: `scripts/crown.sh <clicks>`.
- Waypoints: `scripts/seed-targets.sh <bearing>:<color-place>[:<meters>] ...` puts waypoints in the app's database with the app stopped (`many` and `none` are also accepted). Start the app once first so the database exists.
- Taps by text: `scripts/tap-text.sh <text>`. Haptics the system recorded: `scripts/haptics.sh mark` then `scripts/haptics.sh since <mark>`.
- Fused location is delivered only while the app is in the foreground, and needs `scripts/geo-feed.sh` running. The emulator cannot lower the reported sensor accuracy and has no vibration motor.
